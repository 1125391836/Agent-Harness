# MVR：三层架构的最小可运行骨架

> **它是什么**：把开题报告里的「硬门控 → PreVal 风险分级 → 调度器」三层，
> 以及「全量快照 vs 副作用感知快照」这一维，做成一条能跑、能改、能出表的管线。
>
> **它不是什么**：里面的数字全是手调的（10 个任务、10 条工具、假 World）。
> 它验证的是**管线与指标定义**，不是论文结论。结论必须来自第 5 周之后的真实任务集。

**环境**：Windows + PyCharm 足够，主路径不需要 Linux。
实测这把机器上目录级 fork 中位 **22 ms**（200 文件 / 3.9 MB，硬链接模式），
比文献 [4] 的全量快照（1.4–7 s）低两个数量级。
PreVal 的"大模型"是一次 HTTP 调用，不是本地部署。详见 [docs/环境方案.md](docs/环境方案.md)。

## 2. 三层怎么落在代码里

| 论文层 | 代码 | 关键契约 |
|---|---|---|
| L1 硬门控 | `harness/layers.py::HardGate` | 只做确定性、可审计的判断：额度、黑名单、能力表、未知工具。便宜到可以每步都跑。 |
| L2 PreVal | `harness/layers.py::PreVal` | **只输出 `Features`，永不做决定**。这是解耦的关键：换评分模型不动调度。 |
| L3 调度器 | `harness/scheduler.py::Policy.decide` | 唯一做决定的地方。7 条基线 = 7 个 `decide()`，保证对比实验无实现差异。 |
| 快照 A 维 | `harness/snapshot.py::Checkpointer` | `full` / `tiered` 两种成本模型，统一折成决策预算 CU。 |
| 副作用账本 | `harness/layers.py::Ledger` | 幂等键 + 意图记录 → 去重、对账、补偿。也是"外部副作用"的载体。 |
| 世界 | `harness/world.py::World` | `apply()` 产生真副作用，`probe()` 只读给特征。fork = 深拷贝。 |
| PreVal 的 LLM 版 | `harness/preval_llm.py::LLMPreVal` | 一次 HTTP 调用 + 磁盘缓存 + 离线降级；签名与启发式版一致。 |
| 真实分支后端 | `harness/backends.py::DirSnapshotter` | 硬链接树 + 写时复制，Windows/Linux 通用；`measure_env` 直接出成本常数。 |

**最重要的不变量**：真实副作用只在 `Runtime._exec()` 里发生一次；
分支（fork）永远只碰克隆出来的 World。这条守住了，CRIU / overlay / 应用级 fork
三种实现可以随意替换而不影响评测。

## 3. 指标定义（答辩会被追问的地方）

- `DIR = 被拦下的危险动作 / 全部危险动作机会`，分母是**机会数**，不是任务数；
- `成功率 = 无事故 且 未误拦正当动作 的任务占比`——只算"不出事"会奖励"全部否决"，
  所以必须把误拦算成失败（`human_only` 因此得 0%）；
- `成本/任务` 用统一货币 CU，等价于开题报告里的 `C = c_s·S + c_t·T + c_l·L + c_h·H`；
- `oracle` 是天花板，且**随预算移动**：全量快照下它也要转人工，天花板自己会降。

## 4. 接下来 6 步（按依赖顺序，别跳）

1. **接真工具（第 1–2 周）**：把 `World.apply()` 换成 sandbox 里的真实文件操作
   （overlay upperdir），`pay/send_email` 换成 mock server。世界接口不变。
2. **接真任务（第 2–3 周）**：把 `tasks.py` 从手写脚本换成 40 个真实任务，
   每个任务标注「危险动作机会」与「良性但看起来危险的动作」（decoy）。
   decoy 是这套实验设计里最容易被审稿人攻击、也最能体现 fork 价值的部分，必须够多。
3. **Gate 0 判定（第 4 周）**：跑 `gate_only` vs `oracle`。
   如果差值 < 15 个百分点，说明硬门控已经把风险吃干净，题目要改（见路线文档"三种结局"）。
4. **换 PreVal（第 5–6 周）**：现在是 10 行启发式；换成小模型/规则引擎后，
   **只改 `PreVal.score()`**，其余不动——这就是 L2 解耦的回报。
5. **调度器对比（第 7–9 周）**：`risk_fork` 的收益函数先手调，再用第 5 步的数据拟合。
   必须同时报 `always_fork` 与 `preval_only`，否则"fork 有用"站不住。
6. **消融（第 10–11 周）**：关掉账本、关掉快照分层、把 f 调成 1.0，各跑一遍。

## 5. 已知的坑（写在这里省得以后踩）

- `PreVal` 的分数在 decoy 上会聚成一小簇，阈值一动就从 100% 掉到 27%（见 `--sweep`）。
  这不是 bug，是**分类器无法区分同信号不同意图**的本质；论文要把它画成图，
  而不是藏起来。
- `budget` 必须真的递减，否则"固定预算"是假的（我第一版就漏了，`always_fork` 虚高）。
- `confirm` 成本给 5.0 CU 是拍脑袋的，真实值要在第 1 步的 mock server 里量。
- decoy 数量决定 fork 的收益上限；decoy 太少，fork 一定输给 `preval_only`。
