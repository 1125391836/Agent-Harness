# 环境方案：Windows + PyCharm 能不能做这个课题

**结论：能。你的主路径不需要 Linux。**

组员在 Linux 上，是因为他做的是 CRIU / overlayfs 那一层——那是**对照组**，不是你的主路径。
你的方案本来就是"应用级 fork"（深拷贝上下文 + 目录级分支 + 重建工具会话），
这三件事 Windows 全都能做。下面是要点和迁移清单。

---

## 1. 先厘清一件事：PreVal 的"大模型"是什么

组员说"PreVal 需要一个大模型"，指的**不是**在你电脑上训练或部署一个模型，而是：

```
你的程序  --HTTP-->  模型服务（DeepSeek / Qwen / GPT…）  -->  返回一个 0~1 的风险分
```

也就是说，它和你打开网页聊天没有任何技术差别。不需要 GPU、不需要 Linux、
不需要 CUDA，Windows 上一个 `pip install openai` 就完事。

代码已经写好了：`harness/preval_llm.py`。三个工程约束都处理了：

| 约束 | 做法 | 为什么必须 |
|---|---|---|
| 不能依赖网络 | 没 key / 超时 / 解析失败 → 自动退回启发式 `PreVal` | 实验要能离线复现，答辩现场断网也得跑 |
| 不能重复烧钱 | 按 `(动作, 上下文摘要)` 做磁盘缓存 `.cache/preval/` | 12 周里同一批实验要重跑几十次 |
| 输出必须可控 | 强制 JSON、`temperature=0`、正则兜底解析 | 裁判模型输出不稳定会污染整条实验 |

已验证：`python -m unittest mvr.tests.test_platform` 里那条 `test_without_key_degrades_to_heuristic`。

## 2. 你机器上的实测（刚跑的，不是估算）

```
平台     : Windows-11
工作区   : 200 文件 / 3.9 MB
fork 中位 : 22.1 ms   （硬链接模式）
写时复制 : 0.95 ms/次
```

对照文献 [4] 的六工具基准：CRIU 2GiB 要 1.445 s，Docker 2 GB 要 6.915 s。
**你的分支成本比它们低两个数量级**——这正是"副作用感知快照"值得做的量化依据。

还有一个重要发现：22 ms 里绝大部分是 **200 次文件系统调用**，不是 3.9 MB 的数据。
所以 fork 成本的结构是

```
C_fork ≈ a + b · 文件数      （而不是 a + c · 字节数）
```

这条会直接影响你第五章调度器的设计：**按文件数计费，不是按体积计费**。
写进论文比"快照很贵"这种模糊说法有力得多。

## 3. 哪些事真的只能在 Linux 做，以及替代方案

| 只能在 Linux | 你在 Windows 的替代 | 影响 |
|---|---|---|
| CRIU checkpoint/restore | 不做主路径，只在 E0 做一次对照 | 用 WSL2 跑，或让组员跑一次给你数据 |
| overlayfs | `harness/backends.py::DirSnapshotter`（硬链接树 + 写时复制） | 语义等价，常数项不同，可接受 |
| seccomp / eBPF 系统调用拦截 | 不做系统调用级拦截，改在**工具调用层**拦截 | 这本来就是你的设计：门控在 harness 里，不在内核里 |
| Docker 沙箱执行 | Docker Desktop + WSL2，或直接跑在受限目录 | 只在需要"真沙箱"时用 |

**判断标准**：你的论文主张是"在工具调用层做风险分级 + 分支验证"，
这一层和内核无关。所以 Windows 是充分够用的；把 CRIU 留给对照实验即可。

## 4. PyCharm 配置（15 分钟）

1. `File → Settings → Project → Python Interpreter → Add → Virtualenv`，选 Python 3.11+；
2. Run Configuration：`module name` 填 `mvr.run_demo`，`working directory` 填 `C:\Users\张恒\Desktop\开题报告`；
3. 环境变量（Run Config → Environment variables）：
   ```
   OPENAI_API_KEY=你的key
   OPENAI_BASE_URL=https://api.deepseek.com
   ```
   **别把 key 写进代码，也别提交到 git**；
4. 测试：`Settings → Tools → Python Integrated Tools → Default test runner = pytest` 或直接用 unittest；
5. 可选：`Add Interpreter → WSL`，同一个项目可以一键切到 WSL 里跑对照实验
   （需要 WSL2 + 装好发行版；PyCharm 专业版支持最稳）。

## 6. Windows 上会咬你的六个坑

1. **多进程**：Windows 用 `spawn` 不是 `fork`，并行跑实验必须写
   `if __name__ == "__main__":`，且参数要可 pickle。你的 `Runtime` 里有 `random.Random`，
   可以 pickle，但别把 `World` 传进子进程后再改。
2. **文件锁**：杀毒软件会短暂占用刚写的文件，`os.replace` 偶发 `PermissionError`。
   已做重试余量（`_link_or_copy` 里失败跳过），批量实验建议关掉实时扫描目录。
3. **路径大小写**：Windows 不区分，Linux 区分。分支目录名统一小写下划线。
4. **换行**：`git config core.autocrlf false`，否则和组员 diff 全是噪音。
5. **临时目录权限**：`tempfile` 在受限目录下可能没有写权限，实验输出统一写项目内 `.runs/`。
6. **IO 慢**：机械盘上硬链接也慢，实验数据放 SSD；`measure_env` 的 22 ms 是 SSD 上的数。
